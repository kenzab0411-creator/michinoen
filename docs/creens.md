### 画面2：リクエスト入力画面（旅行者が入力する）

※移動手段がなくて困っている外国人旅行者が、希望を入力する画面です。

1. **見出し:** 「ヒッチハイクをお願いする」
2. **選択肢（ドロップダウン）:** 「人数（1人 / 2人 / 3人以上）」
3. **選択肢（ラジオボタン）:** 「性別（男性 / 女性 / 混合）」
4. **選択肢（ドロップダウン）:** 「年代（10代 / 20代 / 30代以上）」
5. **選択肢（ドロップダウン）:** 「出発地（平泉駅 / 中尊寺 / 毛越寺）」
6. **候補付き入力欄:** 「行き先（例: 中尊寺、または自由に入力）」
7. **選択肢（ラジオボタン）:** 「希望の時間（今すぐ / 15分以内 / 30分以内）」
8. **ボタン:** 「乗せてくれる人を探す」

### 画面3：リクエスト確認・返答画面（ドライバーが見て返信する）

※ドライバーが旅行者の希望内容を確認し、乗せるかどうかを返す画面です。

1. **見出し:** 「届いたリクエスト」
2. **テキスト表示:** 「人数: 1人（20代・女性）」
3. **テキスト表示:** 「区間: 平泉駅 ➔ 中尊寺」
4. **テキスト表示:** 「希望: 今すぐ」
5. **選択肢（ラジオボタン）:** 「迎えに行ける時間（15分後 / 30分後 / 60分後）」
6. **入力欄（1行）:** 「ニックネーム（例: ダリア）」
7. **入力欄（1行）:** 「車の特徴・色（例: 白い軽自動車）」
8. **ボタン:** 「乗せる」
9. **ボタン:** 「今回は見送る」

---

### 画面4：マッチング結果画面（旅行者が結果を見る）

※リクエストを送った旅行者が、返事を待って結果を確認する画面です。

1. **見出し:** 「ドライバーからの返事」
2. **ステータス表示:** 「ダリアさんが 30分後 に迎えに行きます！」
3. **テキスト表示:** 「車の特徴: 白い軽自動車」
4. **合流の合言葉（特大文字）:** 「合言葉: 77」
5. **ボタン:** 「画面を更新する」

### 試してもらう人が最初にさわる画面（主画面）とボタン

* **主画面:** **「画面1：表紙画面」**
* **そのボタン:** 一番下の **「乗せてくれる人を探す」** ボタン

※デモでは、テストする人（外国人観光客の役）には画面2を開いた状態から触ってもらうと、一番困りごとの解決がスムーズに伝わります。ドライバーは画面3で返答する時に、ニックネームと車の特徴を入力します。
